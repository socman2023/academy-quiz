# Версия 8: аудит алгоритма

## Что изменено
- Введены калибровочные поправки для компенсации слишком больших и слишком маленьких зон притяжения персонажей.
- Музыкальный интерес для Илиодора и Евстатия — сильный, но мягкий сигнал, а не жёсткий eligibility-gate. Это не означает, что они единственные музыканты Академии: Кейван также музыкант и певец, но в текущие 25 результатов теста не входит.
- Уточняющий вопрос рассматривает только текущих кандидатов №1 и №2.
- Перед показом уточнения движок виртуально проверяет все его ответы. Если все варианты приводят к одному победителю, вопрос не показывается.
- Общий разделитель G больше не вставляется принудительно: он используется только если реально способен разделить конкретную пару.
- Уточняющее свидетельство имеет повышенный локальный вес.
- Максимум — два уточняющих вопроса.
- Удалено старое правило, которое после двух уточнений могло отбросить их ответы и вернуть первоначального лидера.

## Проверка CI
Production-алгоритм проверяется командой:

```bash
npm run audit:distribution
```

Последний успешный CI-прогон на 100 000 детерминированных случайных прохождений дал:
- диапазон результатов: **2,061%–7,306%**;
- без уточнения: **58,38%**;
- ровно одно уточнение: **38,94%**;
- два уточнения: **2,68%**;
- хотя бы одно уточнение: **41,62%**;
- уточнение изменило первоначального лидера в **19,39%** всех прохождений;
- проверено **41 619** состояний, в которых могло появиться уточнение;
- бессмысленных уточнений, у которых все ветви ведут к одному победителю: **0**.

Минимальная частота в этом прогоне — Ансо (**2,061%**), максимальная — Санко (**7,306%**), то есть производство остаётся внутри согласованного рабочего коридора.

## Контрольные патологические случаи
- `ADADADADADAD`: бессмысленное уточнение больше не показывается.
- `CBCBCBCBCBDB`: разделитель J действительно влияет на результат — ответы A/C ведут к Джаре, B/D к Надиру.

## CI
Workflow проверяет:
1. установку зависимостей;
2. `npm run test:engine`;
3. `npm run audit:distribution`;
4. `npm run build`.
